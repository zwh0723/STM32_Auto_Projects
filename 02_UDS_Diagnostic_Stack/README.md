# UDS 诊断协议栈

## 分层

```
UDS (ISO 14229)        诊断服务
  ↓
ISO-TP (ISO 15765-2)   分段传输
  ↓
CAN (500kbps)          数据链路
```

## 报文格式

**单帧**
```
CAN: 0x02 0x10 0x03            UDS: 10 03（进扩展会话）
CAN: 0x06 0x50 0x03 0x00 0x32 0x01 0xF4   响应
```

**多帧（读 VIN，20 字节）**
```
Tester → ECU:  02 22 F1 90
ECU → Tester:  10 14 62 F1 90 xx xx xx xx xx   (首帧，长度 0x014=20)
Tester → ECU:  30 00 00                        (流控：继续、BS=0、STmin=0)
ECU → Tester:  21 xx xx xx xx xx xx xx         (连续帧 1)
ECU → Tester:  22 xx xx xx xx xx xx xx         (连续帧 2)
```

## 状态机

```
收到帧 → 解析 PCI → 单帧: 直接处理 / 首帧: 存长度回 FC / 连续帧: 校验 SN 后拼接
      → 收齐后交给 uds_handle() → 按 SID 分发 → 校验前置条件 → 组装响应
      → isotp_send() 自动选单帧或多帧
```

## 测试用例

| 请求（CAN Data） | 期望响应 |
|---|---|
| `02 10 03` | `06 50 03 00 32 01 F4` |
| `03 22 F1 86` | `04 62 F1 86 03` |
| `02 27 01` | `06 67 01 12 34 56 78` |
| `06 27 02 48 6E 0C 22` | `02 67 02` |
| `03 2E F1 87` | 未解锁时 `03 7F 2E 33` |

## 踩过的坑

1. **PCI 长度算错**：首帧长度是 12 位（高 4 位在 PCI 低半字节，低 8 位在下一字节）
2. **连续帧偏移量错误**：拷贝时用了 `sent + 1` 而非 `sent`，导致数据整体错位
3. **序号校验缺失**：接收端不校验 SN，跳号时仍拼接，导致数据错乱
